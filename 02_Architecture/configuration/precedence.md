# Configuration Architecture and Precedence

**Read this before editing anything.** Getting precedence wrong is the single easiest way to make a change that
appears to do nothing.

## The chain

```
   Noctalia built-in defaults            (compiled in: src/config/config_types.h)
                ↓
   ~/.config/noctalia/*.toml             ← merged ALPHABETICALLY: lockscreen.toml, rice.toml
                ↓
   ~/.local/state/noctalia/settings.toml ← written by the Noctalia settings GUI — WINS OVER EVERYTHING
                ↓
   validation (schema in src/config/schema/config_schema.cpp)
                ↓
   runtime configuration → components (live reload via inotify on the config dir)
```

For niri the chain is positional rather than layered:

```
~/.config/niri/config.kdl
   include rice/glass.kdl        GENERATED by the shell from [shell.glass]      (niri's one `blur` node)
   include rice/animations.kdl   GENERATED by the shell from [shell.animation]
   include rice/rules.kdl        window + layer rules
   include rice/binds.kdl        keybindings
   include noctalia.kdl          GENERATED palette — MUST BE LAST (later nodes win)
```

## Ownership table

| File | Owner | Hand-editable | Notes |
|---|---|---|---|
| `~/.config/noctalia/rice.toml` | **Zynith (human)** | **Yes — this is the main file** | The design layer: bar clusters, panel geometry, OSD/notification placement, palette source, audio cues, hooks |
| `~/.config/noctalia/lockscreen.toml` | Zynith (human) | Yes | Lock screen composition |
| `~/.local/state/noctalia/settings.toml` | **Noctalia GUI** | **No** | A standing project rule: Zynith never writes here. It silently overrides `rice.toml`, which is a frequent source of "my edit did nothing" |
| `~/.config/niri/rice/rules.kdl`, `binds.kdl` | Zynith (human) | Yes | |
| `~/.config/niri/rice/animations.kdl` | **Zynith Shell** | No | Generated from `[shell.animation]`; validated, atomic, coalesced (ADR‑0015) |
| `~/.config/niri/rice/glass.kdl` | **Zynith Shell** | No | Generated from `[shell.glass]`; holds niri's single `blur` node (ADR‑0016) |
| `~/.config/niri/noctalia.kdl` | Noctalia | No | Palette export; must stay the last include |

## Why alphabetical merging matters

Files in `~/.config/noctalia/` merge in alphabetical order. Until 2026‑09‑25 that forced an awkward rule: the Motion
plugin wrote `motion.toml`, `rice.toml` sorts after it and would have silently won, so `rice.toml` carried a
comment forbidding a `[shell.animation]` table and the plugin scanned for violations.

That arrangement is **retired**. The plugin and `motion.toml` are gone, `[shell.animation]` lives in `rice.toml` as
part of the Zynith preset like every other table, and the shell generates niri's side of it. There is now one
owner per key, which is the point of [ADR‑0014](../../05_Decisions/ADRs/ADR-0014-extend-noctalia-config.md) — see
[ADR‑0015](../../05_Decisions/ADRs/ADR-0015-niri-animation-ownership.md) for how it got there.

## Known precedence incidents

- The bar's `end` widget list and `thickness`/`font_family` are currently set in `settings.toml` and therefore
  override `rice.toml`. This is why the CPU/RAM/temp cluster and the notification bell are absent from the bar
  even though `rice.toml` lists them. **VERIFIED** 2026‑09‑20; documented in
  `06_Reference/troubleshooting/index.md` (symptom "bar widget missing").
- A Phase 1 edit once removed the wrong `font_family` line from `settings.toml` because a regex matched the
  desktop widget's key first. Recovery is documented in `01_Phases/Phase_1/bugs.md`.
- The same pattern, for the lock screen: a Phase 2 editor save put the whole `[lockscreen_widgets]` layout in
  `settings.toml`. Arrays such as `widget_order` are replaced, not merged, so every widget added to
  `lockscreen.toml` afterwards was dropped. **VERIFIED** 2026‑09‑26. `noctalia msg lockscreen-widgets-reset` clears
  that table; see [`composition.md`](../lockscreen/composition.md).

## Live reload

Noctalia watches its config directory with inotify; `noctalia msg config-reload` forces a reload. Most settings
apply without restarting the shell. Exceptions found so far are recorded per-phase; the notable one is
`[wallpaper] carousel`, which is read when the wallpaper panel is constructed, so switching browse surfaces needs a
shell restart.
