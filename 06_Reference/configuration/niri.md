# `~/.config/niri/` — compositor configuration

## `config.kdl` (133 lines)

The entry point. Two things matter more than the rest:

```kdl
spawn-at-startup "sh" "-c" "~/.local/opt/noctalia/bin/noctalia || exec /usr/bin/noctalia"
include "rice/layout.kdl"     // window behaviour preset, generated by the Zynith UI (after the layout block)
include "rice/glass.kdl"
include "rice/animations.kdl"
include "rice/rules.kdl"
include "rice/binds.kdl"
include "noctalia.kdl"        // generated palette — MUST be last
```

1. The **spawn fallback** is why a broken local build cannot leave me without a shell.
2. **Include order is precedence.** Later nodes win, so the generated palette include stays last.

The stock 635-line configuration is preserved verbatim at `config.kdl.save`.

### Input: `Mod` and pointer gestures

```kdl
input {
    // … keyboard, touchpad, focus-follows-mouse …
    mod-key "Super"
}
```

`Mod` is `Super` — niri's default on a TTY already, stated explicitly since 2026‑09‑25 so there is one place to
change it (`mod-key-nested` is left at its default). It drives every `Mod+` binding and niri's native pointer
gestures, which Zynith uses as-is:

| Gesture | Action |
|---|---|
| `Mod` + left-drag | interactive move; right-click while moving toggles floating/tiling |
| `Mod` + right-drag | interactive resize (the edges nearest the press point) |
| `Mod` + middle-drag | view movement (horizontal) / workspace switch (vertical) |
| double-click a resize edge | reset height / toggle full width |

Nothing in the shell emulates or intercepts these. **Do not bind `Mod+MouseLeft` or `Mod+MouseRight`** — niri
documents that such a bind overrides the gesture. None exists in any included file (checked 2026‑09‑25). Verified on
a throwaway floating window: a −300 px drag moved it exactly −300 px; a (−200, −300) right-drag resized it by
exactly that.

## `rice/rules.kdl` (144 lines)

Window rules (corner radius, clip, per-app opacity, blur, floating behaviour, privacy block-out) and layer rules.
Two layer rules matter:

```kdl
layer-rule { match namespace="^noctalia-backdrop"; place-within-backdrop true }
layer-rule { match namespace="^noctalia-notification$"; background-effect { blur true } }
```

## `rice/binds.kdl` (200 lines)

Keybindings ported from my Hyprland configuration. Hardware keys use `cooldown-ms=50` (adjust) and
`repeat=false` (toggles) to cap how fast a held key can spawn `noctalia msg`.

Since 2026‑09‑25 **every bind that spawns `noctalia msg` also carries `repeat=false`** (17 binds: launcher,
wallpaper, clipboard, Control Center, settings, session, bar, lock, …). Before that, holding `Mod+W` re-spawned
`panel-toggle wallpaper` on every key repeat, and the shell log showed the browser opening and closing 13 times in
five seconds. niri-internal toggles (`Mod+Space` floating, `Mod+G` tabbed) still repeat; they spawn nothing.

`Mod+Alt+A` spawns `noctalia msg settings-open personalization` — the Personalization section, opening on its
first group, Motion. It used to open the retired Motion plugin's own panel, and briefly (`8c2b4eb`) the section's
earlier id, `zynith-corner`, which no longer exists.

## `rice/animations.kdl` — generated by the shell

Generated from `[shell.animation]` whenever a config change alters it (ADR‑0015): coalesced over a 300 ms debounce,
checked with `niri validate -c` on a temp copy, installed atomically, then the full config re-validated with
rollback on failure. Hand edits are overwritten by the next change. Animations off produces `animations { off }`.

## `rice/glass.kdl` — generated by the shell

Holds niri's single, global `blur {}` node, generated from `[shell.glass].blur_strength` (ADR‑0016); 50 reproduces
passes 3 / offset 4.0. It is included where the hand-written `blur` block used to sit in `config.kdl`. **Do not add
a `blur` node to `config.kdl`** — niri rejects a duplicate as a config error.

## `rice/layout.kdl` — generated by the Zynith UI

Written from `window.behaviour` in `~/.config/zynith/shell.json` (Zynith 2.0, Stage 1). Values:

- `config` (default): an empty fragment, so the hand-written `layout {}` block applies as written;
- `scrolling`: windows open at their own width, and the focused column is centred when it overflows;
- `tiling-like`: half-width columns with ⅓ · ½ · ⅔ · full presets, and no resizing of existing windows.

Every write goes through `NiriConfig` in Zynith.Native:

1. the fragment is staged as `rice/layout.kdl.zynith-new`;
2. `niri validate -c` runs on a probe copy of `config.kdl` that includes the staged fragment;
3. only if that passes is the fragment renamed over the old one, and niri reloads on its own.

A rejected fragment leaves nothing behind. Only the main UI instance writes; the Settings app edits `shell.json`.

The `include` line was added on 2026‑10‑02, directly after the `layout {}` block. The `config.kdl` from before that
edit is in `~/.config/rice-backups/20261002-141224-zynith-layout-include/`. To undo, remove the three-line
`include "rice/layout.kdl"` block.

## `noctalia.kdl` (32 lines) — generated

Palette export from Noctalia. Regenerated whenever the wallpaper or theme changes.

## Applying changes

```sh
niri validate && niri msg action load-config-file
```
niri also live-reloads on file change (mtime polling), but validating first avoids a broken config being loaded.
